# Page Spec（页面需求规格）

Page Spec 是 PRD 与页面实现之间的合同。生成代码前先完成它；信息不足时记录假设，不要补写成产品事实。

## 必填结构

### 页面元数据

- 页面名称与英文短名
- 页面类型：`list-management`、`detail` 或 `form`
- 用户角色与核心任务
- 入口、退出和上下游页面
- 数据来源：真实接口、用户提供样例或受控模拟数据

### 已确认事实

只记录 PRD、用户明确说明或当前项目源文件能够证明的内容，并注明来源。

### 信息架构

按阅读和操作顺序列出页面区域。列表页至少描述页头、筛选、批量/主要操作、结果区和分页；详情页描述摘要、状态、信息组和操作；表单页描述分组、字段、校验与提交结果。

### 组件映射

每项包含：需求元素、选择的 QIZHI 组件、源章节/行号、正式类名、`data-*`/ARIA、复用或扩展结论。不能证明来源时写入能力缺口。

### 状态矩阵

按相关性覆盖：默认、hover、focus-visible、active、disabled、loading、empty、error、success、no-permission、partial-success。说明触发条件、用户可见反馈和恢复路径。

### 交互与数据

记录输入、输出、校验、确认、取消、焦点恢复、重复触发、失败恢复和模拟数据范围。危险操作必须说明可逆性和确认方式。

### 响应式与可访问性

记录 1440、1024、375 三个视口的布局变化，以及键盘路径、可见焦点、语义元素和 ARIA 状态。

### 假设

只采用可逆、低风险并且不改变主流程的假设。说明为什么采用、如何替换和影响范围。

### 未决问题

列出需要产品、前端或后端确认的业务规则；权限、审批、删除语义、接口副作用和敏感数据不得自行决定。

### 阻塞项

缺少后会导致主流程方向变化、合规风险或大量返工的内容。存在阻塞项时先停在 Page Spec，不生成误导性页面。
