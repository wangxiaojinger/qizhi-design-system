# QIZHI React 组件官网展示规范

本文定义所有已迁移 React 组件的官网共性。组件特有的文案、Demo 和 API 由各自契约决定，不得重新设计下列公共规则。

## 1. 文档与组件边界

- 官网预览必须从 `@wangxiaojinger/qizhi-react` 导入正式组件。
- Demo 容器、文字说明和页面栅格不是公共组件 API。
- 同类官网操作必须复用相同的正式 Button、Icon 和反馈协议。
- 官网不得用页面 ID 决定公共组件行为。

## 2. Demo 结构

每个 Demo 必须具有：

1. 在整个单页文档 DOM 中全局唯一的稳定锚点；组件 API 锚点使用 `<component>-API`，不得复用裸 `API`。
2. 标题和独立描述，描述不得重复属性名称充数。
3. 直接渲染的 Demo TSX。
4. 查看/收起代码、复制代码和可访问反馈。
5. 与预览同源的代码内容。

默认操作区：

- 与 Demo 右边框对齐。
- 与 Demo 底部保持 12px 间距。
- “查看代码”使用 `CodeIcon`，“复制代码”使用 `CopyIcon`。
- 按钮调用正式 `Button`，不得手写近似按钮。

## 3. 代码展示

- React Demo 使用标准 TSX 可复制代码，导入路径为 `@wangxiaojinger/qizhi-react`。
- 代码预览和复制内容不得手写第二份。
- 展开后直接显示代码内容。禁止显示 `Demo.tsx`、真实文件名、文件路径、语言徽标或其他代码块标题，除非用户在当前任务中明确要求。
- Demo 源文件的内部命名只用于工程组织，不属于规范站信息架构，不得直接暴露到界面。
- 代码区字号为 13px，默认文本色为 QIZHI 次级文字色。
- 统一使用公共高亮器，不在各组件文档中另写正则。
- JSX 标签、属性、关键字、字符串和布尔值的色彩映射属于全局文档规则。

## 4. API 元数据

每个属性至少包含：

```ts
interface ComponentApiItem {
  name: string;
  description: string;
  type: string;
  defaultValue: string;
}
```

规则：

- 类型与默认值必须和 TypeScript 契约、运行时实现一致。
- 描述必须说明行为或限制，不得只写“设置 X”。
- 类型联合、默认值和属性组合保留机器可读结构，供搜索和 AI 消费。
- 只有描述中需要特别指认的 API 标识符由数据显式标记为行内代码；禁止自动识别所有英文并加背景。

## 5. API 表格视觉基线

| 内容 | 字体 | 字号 | 颜色 | 背景 |
|---|---|---:|---|---|
| 参数名 | Inter | 14px | 正文黑色 | 无 |
| 描述正文 | Inter + 中文系统回退 | 14px | 正文色 | 无 |
| 特别指认的 API 标识 | Menlo | 12px | 次级文字色 | `color-fill-2` |
| 类型 | Inter | 14px | `magenta-6 / #F5319D` | 无 |
| 默认值中的英文 | Inter | 14px | `magenta-6 / #F5319D` | 无 |
| 默认值中的非英文或缺省符 | Inter + 字体回退 | 14px | 正文色 | 无 |

字体判断基于语义，不基于单词是否为英文。参数名、类型和默认值处在结构化列中，不加灰色背景。

## 6. 响应式与无障碍

- 桌面、窄屏和手机分别在 1440、1024、375 视口验收。
- API 表格可以在小屏水平滚动，但不得让整个页面产生水平滚动。
- 所有操作控件必须使用语义元素、可见焦点和中文可访问名称。
- 复制成功或失败反馈通过 `role="status"` 暴露。
- 不用“元素存在”代替几何对齐、最终计算样式和截图人工检查。

## 7. 变更规则

- 用户修改公共展示规则时，应修改本文和公共测试，而不只修改当前组件的局部样式。
- 组件特有规则留在组件契约中，不污染全局文档样式。
- React 文档岛挂载后必须触发 `qizhi:react-island-ready`，由文档壳层基于新 DOM 重建右侧目录；不得用 `qizhi:route-rendered` 代替。
- 修改后必须更新自动测试并人工查看截图。
- 任何新增的用户可见元素都必须能指向旧规范站证据、本文的明确条款或用户当前任务的明确要求；无法指向时必须删除，不得保留为“辅助信息”。
