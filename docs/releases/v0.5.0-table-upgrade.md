# v0.5.0 Table 升级接入说明

从 v0.5.0 起，推荐配置已经是 Table 组件自身的默认值。业务升级组件包后，无需复制文档示例的开关配置；页面原有的显式配置仍优先。

## 升级

```bash
pnpm add -E @wangxiaojinger/qizhi-react@0.5.0
# 项目直接依赖 Tokens 时，同步升级：
pnpm add -E @wangxiaojinger/qizhi-tokens@0.5.0
```

沿用现有 GitHub Packages 访问配置，不将访问令牌提交到仓库。React 和 React DOM 需要19或以上版本。应用入口全局引入一次样式：

```tsx
import "@wangxiaojinger/qizhi-react/style.css";
```

升级后须重新构建、部署业务项目；仅查看新版文档不会更新业务项目中的组件包。

## 不额外配置时的效果

默认开启：悬浮高亮、表头、普通字符串／数字的两行省略、实际截断时的全文提示，以及640px容器固定列断点。表格尺寸为 default。

默认关闭：外边框、单元格边框、列调宽、列移动、列显隐、行选择和行拖动；加载初始状态为关闭，分页仍由业务配置。

同时默认提供缺失原始值 `-` 占位、空态上下各36px留白。开启加载时默认仅遮罩数据区并保留原记录；低于或等于640px容器宽度时解除已声明固定列的固定状态，不自动推断或指定任何业务固定列。

最小调用即可获得这些默认值：

```tsx
import { Table } from "@wangxiaojinger/qizhi-react";

<Table rowKey="id" columns={columns} dataSource={rows} />;
```

`columns` 和行主键仍由业务定义。复杂自定义渲染的按钮、标签和输入控件不会被默认两行省略裁切；0、false及自定义render保留原语义。

## 按需开启或覆盖

```tsx
// 开启边框与列调宽：
<Table
  rowKey="id"
  columns={columns}
  dataSource={rows}
  border
  columnCustomization={{ resize: true }}
/>;

// 只开启列移动和显隐，不自动开启调宽：
<Table
  rowKey="id"
  columns={columns}
  dataSource={rows}
  columnCustomization={{ reorder: true, visibility: true }}
/>;

// 示例：恢复自然换行，保持固定列，关闭缺失占位和额外空态留白：
<Table
  rowKey="id"
  columns={columns}
  dataSource={rows}
  ellipsis={false}
  fixedBreakpoint={false}
  emptyCell={null}
  emptyPadding={0}
/>;
```

列级 `ellipsis` 优先于表级配置：`false` 自然换行，`true` 保留旧单行原生title语义，`{ rows: 2, tooltip: true }` 使用两行及按需全文提示。需要全表加载遮罩时显式传 `loading={{ spinning: loading, scope: "table" }}`。

已有业务封装若显式传入 `ellipsis={false}`、自定义空态间距或加载范围，这些配置会继续生效。希望采用组件新默认时，应移除对应旧覆盖值；不会强行覆盖业务选择。

## 列布局保存与升级边界

可序列化布局继续使用 schemaVersion=1，无需仅因升级组件版本清空配置。保存过的列宽和显隐状态继续按当前列定义规范化；关闭调宽入口不会自动清除用户已有尺寸。权限列过滤、布局存储、网络请求、服务端分页和排序仍由业务负责。

使用长期稳定的column key。业务改变列含义时迁移布局或升级独立业务布局版本；组件版本号与业务布局版本号不是同一个字段。旧 `columnCustomization.settings` 继续保留类型兼容，但入口由 `visibility` 控制。
