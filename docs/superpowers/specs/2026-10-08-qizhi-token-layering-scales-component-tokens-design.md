# QIZHI Token 分层、通用尺度与组件 Token 设计

## 目标

在不破坏现有消费者、不改变当前计算样式和组件视觉的前提下，为 `@wangxiaojinger/qizhi-tokens` 建立可持续扩展的 Token 架构，并让首批高频 React 组件真实消费组件 Token。

本阶段的成功标准：

- 现有公开 CSS 变量全部继续输出，名称、值类型和最终计算值保持不变；
- 现有消费者对旧变量的运行时覆盖仍能传递到迁移后的组件；
- 每个公开 Token 都具有明确的分层和生命周期信息；
- 建立通用字体、行高、间距、控件高度、边框、阴影、动效和浮层层级尺度；
- Button、Input、Select、Modal 使用公开组件 Token，迁移前后计算样式一致；
- Table 只建立映射，不修改当前存在未提交改动的实现；
- 自动化检查能够阻止旧变量消失、值类型变化、别名引用断裂和生成产物过期。

## 非目标

本阶段不删除旧变量，不统一或更换品牌色，不调整背景层级的实际色值，不实现暗色或紧凑主题，不批量改造全部组件，也不发布新包或升级外部消费项目。

## 设计原则

### 兼容优先

旧公共变量在本阶段继续作为兼容入口。新 Alias Token 和 Component Token 默认引用现有公共变量，使以下消费者覆盖继续有效：

```css
:root {
  --primary-6: 80, 120, 255;
}
```

迁移后的 Button 仍必须从这项覆盖得到主色。不能普遍采用“旧变量改为指向新变量”的方式，因为这会使既有运行时覆盖失去向新组件 Token 的传播能力。

### 分层与生命周期分离

每个 Token 增加：

- `tier`: `seed | map | alias | component`；
- `status`: `stable | deprecated`；
- `replacedBy`: 仅弃用 Token 使用，指向推荐替代项。

`tier` 表达派生职责，`status` 表达公共契约生命周期，二者不能混用。所有别名引用保持单向无环。

### 不改变值类型

RGB 通道变量继续保持通道值，例如 `51, 102, 255`。不能直接改成 `#3366ff`，否则既有 `rgb(var(...))` 和 `rgba(var(...), alpha)` 用法会失效。长度、数字、百分比和完整颜色同样需要保持类型兼容。

## Token 分层

### Seed Token

表达最小设计意图，包括品牌主色锚点、状态色锚点、基础字体、基础字号、基础圆角和基础控件高度。Seed 不直接承担具体组件用途。

### Map Token

表达从 Seed 扩展出的成组尺度，包括完整色板、字号、行高、间距、控件高度、圆角、边框宽度、阴影、动效和层级。

### Alias Token

表达跨组件共享的使用语义，包括文本层级、背景表面、边框、填充、交互状态、焦点环和遮罩。现有 `color.text.*`、`color.border.*`、`color.fill.*` 等归入本层。

### Component Token

表达单一组件可以独立覆盖的视觉契约。组件 Token 只能引用 Seed、Map 或 Alias Token，不能引用其他组件 Token。

## 通用尺度

第一阶段新增以下最小集合，数值取自当前组件已稳定使用的值，因此不引入视觉变化：

- 字号：12、14、16、18、20、24、28、32px；
- 行高：18、20、22、24、26、28、30、32、36px；
- 间距：0、2、4、6、8、12、16、20、24、32、40、48px；
- 控件高度：24、28、32、36px，分别对应 mini、small、medium、large；
- 边框宽度：0、1、2px；
- 阴影：低层容器、普通浮层、模态层；
- 动效时长：160、200、300ms；
- 缓动：standard、enter、exit；
- 浮层层级：sticky、dropdown、modal、message/tooltip。

命名使用职责与尺寸组合，不使用只适用于某个页面的业务名称。数值相同但职责不同的 Alias 或 Component Token可以并存。

## 首批组件 Token

### Button

覆盖四档高度、水平内边距、图标间距、圆角、字号、边框宽度、主按钮各状态颜色、禁用状态、焦点环和动效。

### Input

覆盖四档高度、水平内边距、圆角、字号、边框状态、背景、禁用状态、焦点环、图标尺寸和动效。

### Select

覆盖四档高度、水平内边距、圆角、字号、边框状态、背景、禁用状态、浮层阴影、选项高度和动效。

### Modal

覆盖层级、遮罩、圆角、阴影、头部高度、标题字号、内容与底部内边距、操作间距以及进入动效。

### Table

映射表记录其表头背景、单元格内边距、字号、行高、边框、固定列层级和行状态候选项。本阶段不修改 `table.css`，避免与当前在途改动冲突。

## 清单与生成产物

`packages/qizhi-tokens/src/tokens.json` 继续作为唯一编辑源。生成脚本和类型声明扩展 `tier`、`status`、可选 `replacedBy` 字段；生成的 CSS 仍只输出 CSS 变量，不输出元数据。

新增机器可读的兼容映射，至少包含：

- 原变量名；
- 处理方式：保留、兼容别名、新增或弃用；
- 推荐新变量；
- 值类型；
- 迁移说明。

兼容映射由源清单生成或验证，不能成为第二个可独立修改的事实源。

## 消费迁移

Button、Input、Select、Modal 的 CSS 仅将已有字面量或旧 Alias 替换为新 Component Token。每个 Component Token 的默认值引用旧公共变量或等值 Map Token，确保：

1. 未覆盖变量时，迁移前后计算值一致；
2. 覆盖旧公共变量时，迁移后的组件继续响应；
3. 覆盖组件 Token 时，只影响目标组件。

不为运行时数据建立公共设计变量。进度百分比、步数、动态宽度等仍属于组件内部自定义属性。

## 兼容性测试

实施遵循测试驱动：先增加失败测试，再修改清单和组件。

自动化至少覆盖：

- 旧公开变量名称全集仍然存在；
- 旧变量的原始值类型保持一致；
- 所有 Token 都具有合法的 `tier` 和 `status`；
- `deprecated` Token 必须具有可解析的 `replacedBy`；
- Token 引用无缺失、无循环，且层级依赖方向合法；
- 新通用尺度和值符合批准的基线；
- 四个首批组件 Token 全部存在；
- 模拟覆盖旧变量时，新组件 Token 仍能解析到覆盖值；
- 生成的 CSS、JavaScript、JSON 和类型声明保持最新；
- Button、Input、Select、Modal 现有组件测试、类型检查和构建通过。

视觉验收比较迁移前后的关键状态：默认、hover、active、focus-visible、disabled、error/warning、各尺寸和浮层打开状态。检查 1440、1024、375px 视口，但不借本任务改变响应式设计。

## 版本与发布

该阶段只增加兼容能力，适合次版本发布，不应作为破坏性主版本。代码完成并验证不等于已发布；发布、外部项目升级和线上文档同步均需单独授权与独立回执。

执行结果最多记录为 `candidate_pass`；独立最终验证保持 `pending`，除非实际完成独立验收。
