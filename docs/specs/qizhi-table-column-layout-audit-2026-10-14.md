# QIZHI Table 列宽能力审查与补充方案

日期：2026-10-14。状态：列宽能力已在本地实现；公开支持组合与合法宽度预算的范围已通过独立验收。验证及历史失败记录见 [列宽验证记录](../verification/table-column-layout-2026-10-14.md)。

## 已确认实现

证据：`packages/qizhi-react/src/table/Table.types.ts`、`Table.tsx`、`table.css`。

Table 是自研原生表格，不是 AntD 封装。默认仍为全宽 fixed 布局。没有新增约束的旧配置保留原生宽度分配：数字 width 总和加辅助列各 48px 成为表格 min-width，scrollX 可覆盖。未声明宽度的列分享剩余空间；全部声明后仍可能被浏览器扩张，声明宽度不是严格锁宽。

新增 colgroup 统一表达业务列和辅助列，隐藏表头仍保留宽度。固定列通过实际 col 宽度计算同侧累计偏移，不依赖声明宽度。ResizeObserver 只观察容器、表格和固定列的 col，不扫描单元格或当前页内容；偏移按列数线性计算。默认自然换行和显式 ellipsis 保留，复杂 render 的完整提示由业务处理。

## 已补齐能力与组合限制

| 能力 | 实现 | 使用边界 |
| --- | --- | --- |
| 无表头列宽 | colgroup 与表头解耦 | 旧式原生布局实际宽度仍受容器分配影响 |
| 多固定列 | 实际列宽的累计偏移 | 辅助列自身不固定；左右固定列加前置辅助列的实际总宽应小于容器，须检查 scrollLeft=0；跨固定边界的合并单元格不在新增保证范围 |
| minWidth / maxWidth / grow | fixed 下确定性数字分配 | 所有 width 必须是数字或缺省；不得混用字符串 scrollX |
| tableLayout | fixed / auto，默认 fixed | auto 仅提供原生 minWidth，不应用 maxWidth/grow；ellipsis 不自动切换算法 |
| align | left / center / right，默认 left | 表头、排序控件、单元格一致；业务 onCell.style 仍保留覆盖路径 |
| layoutMode | fill / compact，默认 fill | compact 默认 auto；显式 fixed 加约束时采用稳定数字预算 |

数字分配以 width 或 minWidth 或 120px 为基准，grow 正数按权重分配，受 maxWidth 限制。只有 grow 列在容器不足时缩减，最低为显式 minWidth 或缺省 120px（若显式 maxWidth 小于缺省下限则以 maxWidth 为预算）；非 grow 列保持预算。显式 minWidth 大于 maxWidth 时最小值优先。所有上限耗尽后表格右侧可留白，不强行铺满。数字 scrollX 作为增长目标，上限优先。style 的显式布局覆盖由业务承担一致性责任。

全局默认无法自动知道自定义 ReactNode 的合理宽度、业务合法内容上限和未来语言文案。业务仍需声明稳定列宽；不得扫描当前页并把测量结果当作全局标准。

## 实施兼容性

新增属性需可选，既有 width、scrollX、ellipsis、密度、换行和业务操作语义保持兼容。显式业务设置优先；不批量改业务页面。TokenHub 的 8 行分页、操作全部可见和首尾固定属于该项目规则，不升为组件全局默认。

不通过 onCell 的局部 max-width 假装提供可靠的列级 maxWidth。不新增字段名推断、每次渲染全量 DOM 测量或自动操作收纳。复杂合并单元格跨固定边界、响应式隐藏、虚拟滚动、服务端筛选协议和拖拽调整列宽仍不在此次范围；仅验证现有合并、嵌套、树形、排序等能力兼容。

## 示例与验收

第 12 个同源 Demo「列宽与自适应」展示受约束弹性列、compact、auto、隐藏表头与对齐、多固定列。浏览器独立测试夹具覆盖 3/5/10 列、短长内容、选择+展开辅助列、多侧固定列、分页/排序/空态/加载及同视口容器变化。复杂合并、嵌套、树形和密度走既有 Table E2E 回归。

在 1440/1024/375 视口及同一视口不同容器宽度验证：页面 scrollWidth 不超过 clientWidth（允许 1px 舍入）；宽度预算可容纳时内部无横向溢出（允许 1px）；不足时可滚动至末列；固定列不重叠；同列 th/td 宽差不超过 1px；配置稳定的列在数据/状态变化前后宽差不超过 1px（容器不变）。为无 width 的弹性列单独检查剩余空间，不要求其保持固定像素。

每个 Demo 的列宽预算必须写明表头/控件/格式依据，不能用“合理”“明显”代替验收。声明测试、浏览器和性能的实际结果；文档更新不等于运行时能力实现或独立验收。
