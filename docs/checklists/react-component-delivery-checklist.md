# QIZHI React 组件交付检查清单

> 每迁移一个组件复制本清单。未勾选项必须在交付报告中说明原因，不得用“应该正常”代替验证。

## A. 任务启动

- [ ] 已从头到尾阅读 `AGENTS.md`。
- [ ] 已阅读 `docs/methodology/react-component-migration.md`。
- [ ] 已阅读 `docs/standards/react-component-docs.md`。
- [ ] 已盘点当前工作区改动，未覆盖用户内容。
- [ ] 已确定本次只迁移一个组件类别或经过明确授权的范围。

## B. 证据与契约

- [ ] 已盘点原规范站全部相关 Demo，没有将“添加”误作“替换”。
- [ ] 已搜索 Token、图标、类名、交互脚本和所有消费场景。
- [ ] 已列出保留、修改、删除、待定能力。
- [ ] 已创建 `docs/specs/qizhi-<component>-contract-v1.md`。
- [ ] Props、值域、默认值、组合规则和明确不支持的能力已审定。
- [ ] DOM、原生属性、ref、事件、键盘、焦点和 ARIA 已审定。
- [ ] 参考库能力没有在无 QIZHI 证据时被自动加入。

## C. 正式组件包

- [ ] 实现位于 `packages/qizhi-react`。
- [ ] 类型契约与运行时实现一致。
- [ ] 公共类名、状态类和 Token 均使用 QIZHI 命名。
- [ ] 图标来自 QIZHI 图标库，已检查 `currentColor`、透明度和对齐。
- [ ] 新行为有先失败后通过的契约测试。
- [ ] 正式组件和类型已从 `@wangxiaojinger/qizhi-react` 导出。
- [ ] 包构建产物可导入，CSS 入口有效。

## D. 官网和元数据

- [ ] 已完成“旧站可见元素 → React 可见元素”逐项对照，每个新增 UI 都有旧站、公共规范或用户明确要求的证据。
- [ ] Demo 导入并渲染 `@wangxiaojinger/qizhi-react` 的正式组件。
- [ ] 预览、查看代码和复制代码来自同一 TSX 源文件。
- [ ] 已保留所有经审定 Demo，顺序与契约一致。
- [ ] 文档操作复用正式 Button、Icon 和反馈协议。
- [ ] API 元数据与 TypeScript 和运行时默认值一致。
- [ ] API 表符合 `docs/standards/react-component-docs.md`，没有局部重新设计。
- [ ] 机器可读元数据能表达属性组合、限制和能力缺口。
- [ ] Demo 与 API 锚点在整个 SPA 中全局唯一，React 岛挂载后已触发右侧目录重建事件。
- [ ] 代码区展开后直接显示代码，没有 `Demo.tsx`、文件路径、语言徽标或其他未经授权的附加 UI。

## E. 状态和无障碍

- [ ] default、hover、active、focus-visible、disabled、loading 已按契约验证。
- [ ] 键盘路径、关闭/取消路径和焦点恢复已真实操作。
- [ ] 仅图标控件具有可访问名称。
- [ ] 禁用、加载和错误状态的事件、焦点和 ARIA 均与契约一致。
- [ ] 动效兼容 `prefers-reduced-motion`。

## F. 自动化与视觉验收

- [ ] `pnpm typecheck` 通过。
- [ ] `pnpm test` 通过，失败用例数为 0。
- [ ] `pnpm build` 通过。
- [ ] 必要时 `node --check script.js` 通过。
- [ ] 1440、1024、375 三个视口通过。
- [ ] 页面和 Demo 无水平溢出，控制台无新错误。
- [ ] 已检查直接子项尺寸、对齐、间距和最终计算样式。
- [ ] 已截取目标状态局部截图并人工查看。
- [ ] 截图存在不等于视觉通过，已记录人工结论。

## G. 交付报告

- [ ] 已列出用户可见变化。
- [ ] 已列出修改文件和各自职责。
- [ ] 已列出真实执行的命令、通过数和失败数。
- [ ] 已列出未完成项、限制和独立验证状态。
- [ ] 未将未提交、未发布或未独立验证的内容声称为已正式发布。
